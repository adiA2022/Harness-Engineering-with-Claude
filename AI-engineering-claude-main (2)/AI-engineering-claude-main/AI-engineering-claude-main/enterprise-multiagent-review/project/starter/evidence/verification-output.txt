## 6. Deterministic correction firing in production

The orchestrator recomputes the report's headline counters from the per-file findings
instead of trusting the model's arithmetic. During the final PR #2 run it caught a
real discrepancy and logged the correction:

2026-08-20 19:54:16 [warn]: Corrected summary counters that disagreed with the findings
{
  "service": "code-review-system",
  "claimed": {
    "totalFiles": 4,
    "overallScore": 36,
    "criticalIssues": 5,
    "highPriorityTests": 8,
    "refactoringOpportunities": 14
  },
  "computed": {
    "totalFiles": 4,
    "overallScore": 36,
    "criticalIssues": 5,
    "highPriorityTests": 8,
    "refactoringOpportunities": 13
  }
}

The model claimed 14 refactoring opportunities; its own fileReviews contained 13.
Earlier runs drifted further (9 critical claimed vs 6 actual; 15/11 vs 13/8), which is
what motivated moving this computation into code. Prose and judgement come from the
agents; arithmetic and provenance come from the orchestrator.
